# 标签 Agent 规格书:全量经文主题标签(Topic → Verses)

> 给 n8n 流水线里的 **Agent 2**。目标功能:Her Bible 新增「按主题找经文」
> (Topics 浏览页,竞品形态见 dailyverses.net)。你的工作是**给整本圣经的
> 每一节打主题标签**——纯内容判断,不碰代码、不需要仓库。产出交下游:
> 工程侧(主 agent)负责机械校验、上传与 app 内实现(§8 是工程侧承诺,
> 保证你交付的数据最终真的变成 app 里的功能)。
> 基线:2026-08-29 业主拍板——全量打标、只存引用、单节为单位、不配图;
> 节日主题(Christmas/Easter/Pentecost/Ascension)作为普通主题保留在词表。

## 0. 与既有功能的关系

- App 已有**关键词全文搜索**(阅读器内)——那是 keyword search;你做的是
  **topic 浏览**(用户点「Hope」看一列精选出的相关经文),两者互补。
- 数据是 **refs-only**:只存"哪卷哪章哪节 ∈ 哪些主题"的坐标边表,不存
  经文文字。App 渲染时按用户当前译本(七本内置圣经之一)现场取文——
  一份数据服务七语,你要翻译的只有主题名。

## 1. 你产出什么(共 67 个文件)

1. `topics.json` — 主题词表(约 150 个主题,含 7 语言名称);
2. `tags/<book_slug>.json` × 66 — 每卷一个标签文件,覆盖该卷**每一节**。

## 2. 数据格式

**坐标一律用 KJV(1769)章节编号**——我们英文底本就是 KJV,词表类公版
资源(Nave's 等)也按 KJV 编号,零转换;其他六个译本的编号位移由工程侧
机械换算,**不是你的事**。

`topics.json`:

```json
{
  "version": 1,
  "topics": [
    {
      "id": "hope",                        // 小写-连字符,恒定不改(app 以此为键)
      "names": {
        "en": "Hope", "zh-Hans": "盼望", "zh-Hant": "盼望",
        "de": "Hoffnung", "fr": "Espérance", "es": "Esperanza", "pt": "Esperança"
      }
    }
  ]
}
```

`tags/psalms.json`(每卷一个;verse 键 = `"章:节"`,单节,无范围):

```json
{
  "book": "psalms",                        // 书卷 slug,见 §2b
  "verses": {
    "121:7": ["hope", "protection", "evil"],
    "121:8": ["hope", "protection"],
    "23:1":  ["god", "trust"]
  }
}
```

- 每节 **0–4 个**标签,按相关度排序,第一位是"最属于"的主题;
- **0 标签合法**(见 §4)——但该节的键仍要出现,值为 `[]`,这样"漏做"
  与"判为无标签"可区分;
- 标签值只允许 `topics.json` 里的 id,一个不许自造。

### 2b. 书卷 slug 与节数(以此为准,不要自造)

书卷 slug 和每章节数以我们语料的公开 index 为准(无需权限,直接 HTTP):

```
https://cdn.jsdelivr.net/gh/sangchy1972/pd-text-corpus@e9df0306d76c8b1bf66aae71fc6e93ed8622c8cc/bibles/en/index.json
```

`{ books: [{ name, slug, chapters }] }`,66 卷。注意坑:启示录 slug 是
`revelation-of-john` 不是 `revelation`。每章的节数直接读对应章文件
(`.../bibles/en/books/<slug>/chapters/<N>.json` → `{verses:[{verse,text}]}`)
——这同时就是你打标签时读 KJV 原文的地方。

## 3. 主题词表(先冻结,再打标)

- 基础词表:业主提供的 ~150 主题清单(Acknowledging…Worship,dailyverses
  同款命名习惯)**全部保留,含节日类**(Christmas、Easter、Pentecost、
  Ascension 与其他主题同等打标——2026-08-29 业主确认);
- 你可以做 ±10% 的合并/增补(如 Judgment 拼写统一、近义合并),但**开工
  前先交词表定稿**给业主过目,冻结后 id 永不再改;
- 7 语言主题名:**EN/PT/ES 三语是重点市场,措辞优先打磨**;中文用通行
  神学词汇(盼望/救恩/恩典…),德法照常;
- id 用英文小写连字符(`holy-spirit`、`end-times`、`self-control`)。

## 4. 打标规则(编辑判断,不是关键词匹配)

1. **单独可读**:这节经文将被"拎出来"单独展示在主题页——它必须在
   **脱离上下文时**仍明确讲这个主题。含有 love 这个词 ≠ 讲 love;
   反之,Ps 121:7-8 一个 love 都没有,却是标准的 protection/hope。
2. **密度参照**(竞品同款):绝大多数被标的节 1–3 个标签,上限 4;
   宁缺勿滥——一节硬塞五个泛主题,主题页就会被水节淹没。
3. **0 标签合法且大量存在**:家谱(begat 链)、人口统计、营地清单、
   礼仪流程、纯叙事过场……判 `[]` 是正确答案,不要为覆盖率硬标。
   预期全书有相当比例的节是 `[]`——这不是偷懒,是编辑判断。
4. **每主题保底**:词表里每个主题最终应有 **≥25 节**高质量命中(核心
   主题如 love/faith/hope 会有数百节,正常)。反向检查发现某主题
   全书 <25 节 → 要么补标遗漏,要么这个主题该在词表定稿阶段就被合并。
5. **公版辅助召回**:Nave's Topical Bible(1896)与 Torrey(1897)可以
   拿来**辅助召回**(防漏)。已验证的现成数据源(主 agent 2026-08-29
   开箱核查过):GitHub `j86schroeder/topical-bible-search`(MIT,2026
   审计数字化版,勘误内置、零未解析引用)——
   - `dist/nave/topics.jsonl`(5,321 主题)+ `dist/nave/assertions.jsonl`
     (77,970 条 topic→单节断言);`dist/torrey/` 同构(620 主题/38,583 条);
   - 断言已结构化:`book`(英文全名,如 "Joshua")+
     `chapterStart/verseStart`,逗号引用已拆成单节,KJV 编号;书名 →
     我们的 slug 用 §2b 的 index.json(name→slug)对照;
   - 用法:先建一张「我们词表 id ↔ nave/torrey 主题 slug(可多对一)」
     映射表——**起手草稿已备好:`docs/topic-map-draft.md`**(115 个自动
     直配 + 43 个已验证的同义候选 + 3 个纯编辑主题,每个候选 slug 都实测
     存在于库中),定稿词表时逐行确认增删;按映射拉候选节;它们是 19
     世纪的命名与取舍,**候选仅供防漏,逐节仍要自判**,不照单全收。
   **不得参考任何现代网站/App 的主题→经文映射**(那是别人的编辑成果,
   版权红线)。
6. **教义稳妥**:标签本身就是解经立场——拿不准某节是否"讲"某主题时,
   用最朴素的读法;争议性归类(如把某节标给 hell/punishment)从严。

## 5. 工作流(按卷推进,66 批)

1. **词表定稿** → 业主确认 → 冻结;
2. 逐卷:读该卷 KJV 全文(§2b 章文件)→ 逐节判标 → 产出 `tags/<slug>.json`;
3. 每卷自检(§7 清单)后交付该卷——**不要攒 66 卷一起交**,先交
   诗篇、约翰福音、罗马书、箴言这类高密度卷,让下游早开工;
4. 全部 66 卷交齐后做**反向 QA**:按主题拉全表,过一遍每主题的
   命中列表(精度抽查 + §4.4 保底检查),交一份
   `topic_stats.md`(每主题命中数 + 抽查结论)。

## 6. 你不做的事

- **跨译本存在性核对**(31k 节 × 7 语言是机械活,工程侧脚本做,含
  已知版本化位移的换算——约翰三书、启示录 12、以西结 20、路加 9、
  哥林多后书 13、诗篇题记行);
- 配图(业主拍板不做一题一图)、经文文本烘焙(refs-only)、任何 app 代码;
- 连续多节范围结构:**数据一律单节**。相邻两节同主题(如 Ps 121:7 与
  121:8)在 app 渲染层自动合并展示——工程侧的事。

## 7. 每卷交付前自检

- [ ] 该卷**每一节**都有键(含 `[]` 的),节数与 §2b 章文件逐章相符
- [ ] 所有标签 id ∈ 冻结词表,无拼写变体
- [ ] 每节 ≤4 标签、按相关度排序
- [ ] 抽 20 节人审:单独可读性成立、无关键词误标
- [ ] JSON 可解析、UTF-8、无尾逗号
