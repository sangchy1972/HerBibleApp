### Permissions

#### App declares broad WRITE_EXTERNAL_STORAGE permission and enables legacy external storage while targeting SDK 35, without using Scoped Storage / the Storage Access Framework.
- **Policy**: **Files and Docs Access Policy**
- **Severity**: 🟡 Important
- **Files**: [AndroidManifest.xml](file://android/app/src/main/AndroidManifest.xml)
- **Evidence**: android/app/src/main/AndroidManifest.xml line 14 declares '<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE"/>' with no maxSdkVersion and no tools:node="remove" (unlike READ_EXTERNAL_STORAGE on line 5 and the media permissions on lines 6-9, which are all removed). Line 26 additionally sets android:requestLegacyExternalStorage="true" on the <application> element. android/gradle.properties lines 67-68 set compileSdkVersion=35 and targetSdkVersion=35. On targetSdk 30+, broad WRITE_EXTERNAL_STORAGE plus requestLegacyExternalStorage is a Scoped Storage violation. The app's actual storage usage is local-only (AsyncStorage in index.ts and expo-file-system app-scoped directories) and does not require broad shared-storage write access.

**Critic Verification**: Evidence confirmed exactly. AndroidManifest.xml line 14 declares '<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE"/>' with no maxSdkVersion and no tools:node="remove", unlike READ_EXTERNAL_STORAGE (line 5) and the READ_MEDIA_* permissions (lines 6-9) which are all removed. Line 26 sets android:requestLegacyExternalStorage="true" on the <application> element. gradle.properties lines 67-68 confirm compileSdkVersion=35 and targetSdkVersion=35. Declaring broad WRITE_EXTERNAL_STORAGE while targeting SDK 35 is an unnecessary permission for an app whose storage is local/app-scoped only; this is a legitimate Files & Documents / Scoped Storage compliance concern with concrete file+line citations. (Confidence: High)
- **Recommendation**: Remove the WRITE_EXTERNAL_STORAGE permission from AndroidManifest.xml (or gate it with tools:node="remove" like the other storage permissions) and delete android:requestLegacyExternalStorage="true" from the <application> tag. For any user document or file selection, migrate to the Storage Access Framework (Intent.ACTION_OPEN_DOCUMENT / ACTION_CREATE_DOCUMENT); continue persisting app data via AsyncStorage and the app-scoped expo-file-system directories, which need no external-storage permission.
